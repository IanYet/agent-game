# 测试与人工检查

[文档目录](../README.md) · [本地开发](README.md)

新增规则测试应描述真实的游戏约束，使用可复现的初始状态或随机种子。不要通过连接器、网络服务或真实模型调用来验证规则。

修改行动入口时先补测试并运行，再改规则实现。各游戏均覆盖直接构造行动及非法提交不改状态：斗地主各类出牌、德州非预设额度加注、保皇不同实体副本与标记牌、象棋非法棋步和升变、花砖各来源及目标行、富饶之城身份与建筑技能次数、宝石支付和阶段限制、掼蛋结构化牌型及贡还、卡坦岛的资源组合／位置／报价／目标／发展卡，以及勃艮第城堡的实体板块、格位、货物与工人预算，以及波多黎各自选人员布置与货船／商品／建筑效果组合。合法行动生成器的随机对局用于验证守恒，不能替代这些独立构造的案例。

## 类型与构建

按改动范围运行 `npm run typecheck`、`npm run build:web` 或 `npm run build:connector`；`npm run build` 可以完成整个项目的类型检查与构建。

改动原生打包时，在对应系统运行 `package:windows` 或 `package:macos`，确认安装包、校验和及构建信息生成成功。发布脚本仍会检查文件完整性和来源，这属于发布流程本身。

## 实际操作

涉及游戏交互时，以 1920×1080 为最低验收分辨率，打开网页检查设置、真人出牌、Agent 直接提交、非法行动纠错、暂停继续和回放。确认观察中没有行动清单，首条消息有完整上下文，后续记录增量送达；更换模型、重连或恢复后重新补全历史。富饶之城还需查看实际初始化规则和盗贼决策提示，确认明确区分王冠与本轮国王身份；技能结果随正常决策送达，没有额外通知任务。涉及连接器时，用实际安装包检查本机连接、模型选择、退出和重新启动。真实推理会使用对应账户额度。

Windows 需要留意不同缩放比例下的窗口与托盘操作；macOS 需要实际确认下载后首次打开、菜单栏、浏览器本地网络权限和退出行为。当前 macOS 包尚未完成 Developer ID 签名与公证。

规则测试通过、构建成功和真实账户对弈是不同结果，只报告本次实际完成的内容。

## 界面预览

页面最低支持 1920×1080。开发服务启动后，打开 `/src/games/preview.html`，逐个切换游戏，分别检查最大人数的「真人 + Agent」和「全 Agent 观战」；公共牌桌、玩家卡与操作按钮应完整显示，不产生布局滚动条。

富饶之城的 `/src/games/citadels/preview.html` 提供八座城区、四张手牌及各身份操作场景，用于检查操作切换时玩家卡高度是否稳定。璀璨宝石的 `/src/games/splendor/preview.html` 提供满背包场景，点击「检查卡牌动画」后可按真实规则拿取宝石、购买、预留、暗抽和推进行动，检查卡牌与宝石移动、选中牌的光照过渡和当局声望。这些预览使用正式牌桌组件，不连接模型，也不读取或写入真实游戏存档。

璀璨宝石的 `/src/games/splendor/gem-colors.html` 用于调整动态背景宝石本色，复用正式材质、灯光、相机和抗锯齿设置。可输入 HEX、旋转、暂停和叠放查看；颜色草稿保存在当前浏览器，点击「复制全部色值」可导出，「恢复全部默认」回到正式配色，草稿不会修改源码或游戏存档。

检查结果写入对应 PR 或发布说明，注明版本、系统、操作与尚未确认的行为。本页保留检查方法。
