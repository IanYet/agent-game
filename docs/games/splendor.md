# 璀璨宝石基础版

[游戏目录](README.md) · [文档目录](../README.md)

本模块采用 Marc André 设计、Space Cowboys 发行的 Splendor 基础版，按 2024 周年版规则书实现，支持 2–4 人。不包含 Duel 或扩展。

## 规则与牌组来源

- [发行商游戏页](https://www.spacecowboys-games.com/game/splendor/)及[英文规则书](https://cdn.svc.asmodee.net/production-spacecowboys/uploads/2025/10/SCSPL01EN_SPLENDOR_RULES_LIGHT.pdf)：人数、资源、四种主要行动、黄金任意替代、预留、10 枚上限、贵族与等轮结束。相同声望时，已购发展牌较少者获胜；仍相同共享胜利。
- [Splendor-AI 的固定牌组](https://roeey777.github.io/Splendor-AI/_modules/splendor/splendor/splendor_utils.html)：Steven Spratley 等为 COMP90054 游戏环境整理的 90 张发展牌与 10 位贵族数值。
- [独立牌组 CSV](https://github.com/nerdvana-ro/splendor-tools/blob/main/cards.csv)与[牌组 JSON](https://github.com/kyle-ip/splendor/blob/main/src/data/card-pool.json)：90 张发展牌的等级、颜色、声望与逐色成本已与上述学术实现逐张核对一致。贵族以学术实现的完整十种要求为准；未采用 JSON 中有差异的贵族条目。
- [发行商验证的 Dized FAQ](https://rules.dized.com/game/vdDSzuu4RsC8F45PsW0TKw/faq)：不足三色时尽可能拿取、不能任意丢弃 token、预留不可丢弃与贵族来访。
- [Asmodee 代表的无行动裁定转引](https://boardgames.stackexchange.com/questions/57737/what-to-do-when-you-dont-have-any-move-available)：完全不能拿取、预留或购买时允许被迫跳过，并展示预留牌证明。引擎只在不存在其他合法主要行动时开放该行动。

[data.ts](../../apps/web/src/games/splendor/data.ts) 是固定数值表，不生成随机卡牌成本。每层独立洗牌，市场取牌后立即同层补牌。贵族随机抽取人数加一，其余离场。

## 牌桌操作

真人直接在公共银行逐颗点选宝石，再按玩家卡上的「拿取宝石」确认。同色两枚与不同色组合由当前合法行动限制，重复点击可取消选择。超出十枚时，点击自己持有的宝石选择退还，恰好选够所需数量后才能按「退还」；黄金也可选择退还。点击市场卡牌或自己的预留牌，操作区显示「购买」「预留」，购买费用不足、预留已满或目标不在市场时相应按钮禁用。购买采用规则引擎的默认支付，优先使用对应颜色的宝石，不足部分用黄金补齐。点击市场行首的牌库按钮选择相应等级，再按「暗抽预留」确认；按钮、预留卡标签与牌背说明统一使用「暗抽预留」。有多位贵族可来访时直接点击牌桌上的合规贵族，再按「邀请贵族」。玩家卡的操作区只保留确认按钮。

选中的宝石直接沿自身轮廓描边，黄金沿金币外圈描边，不增加方框或底色。悬停与键盘聚焦也沿同一轮廓提示。

## 预留与可见信息

市场预留持续显示牌面，与已经公开的取牌记录一致。暗抽预留在真人对局中只向持有者显示牌面，对手看到等级与牌背；公开记录只说明等级。两种预留共用卡下标签，分别标注“市场预留”和“暗抽预留”；牌桌与背包沿用相同的预留顺序，背包筛选时保持剩余卡牌的相对顺序。纯 Agent 对局的观战牌桌与回放显示完整暗抽牌名，保留“暗抽”标注。真人对局结束后开启好奇模式也可查看完整记录。Agent 的观察始终按玩家身份过滤，不因浏览器观战而获得对手的暗抽信息。本地行动记录保留实际暗抽牌，由 `splendorEvents` 统一生成公开或观战记录。

## 卡面与素材

动态背景与其他牌桌共用外包盒碰撞：每颗宝石用一个包住全部几何、带少量余量的盒子，只有 8 个顶点、6 个面。碰撞外壳与视觉切面分开，转动和聚拢时优先避免穿模，尖端附近允许留出空隙。

网页使用本项目自行绘制的宝石图标。动态牌桌背景直接沿用白钻、蓝宝石、祖母绿、红宝石和缟玛瑙的五种轮廓，生成带冠面、腰棱与底尖的三维切面宝石，不放黄金筹码。背景里的蓝宝石与祖母绿使用较深的本色，局部高光与透明度独立控制。独立材质按实际切面计算内部折射与反射，让宝石转动时显出带本色的内部亮面；窄灯面提供局部高光，切面交界不额外描线。内部折射边界采用多点采样平滑，重叠处保留半透明层次，物件不投射阴影。未复制原版卡图或贵族插画。

发展牌按参考卡的 64∶91 比例绘制，贵族卡为正方形。市场在牌桌上水平居中、靠上排列，各行卡牌紧凑排列，直接摆在牌桌表面。卡牌使用暗色底和 2px 圆角外框，内圈细线按比例圆角化，在悬停或键盘聚焦时显示。材质层和鼠标透镜使用相同的圆角裁切；透镜保留宝石的凹刻、切面和当前光照。边框统一由界面绘制；贵族卡与发展牌一样，静止时使用普通描边，悬停后才出现暗金色发光描边。声望使用衬线阿拉伯数字，以叠层刻印表现字面，没有声望时省略。

发展牌使用等高线纹路，贵族卡使用覆盖卡面的错行王冠纹路，不叠加等高线。不绘制常显的中央宝石轮廓或散落宝石纹路。默认光点位于左上角，指针进入后光点平滑移到指针位置，离开后返回左上角。黑色发展牌使用彩虹纹路，白色发展牌使用白光，其他发展牌使用对应的宝石色光晕；贵族的王冠纹路随光照显现，反光统一为金色。卡面宝石在暗处显示为带少量自身颜色的暗色凹刻剪影，被同一光点照亮时才显现完整的彩色切面。费用与贵族的折扣要求按种类一色一行、逐颗并排排列。公共银行位于发展牌右侧，按种类逐行、逐颗显示全部库存；银行与玩家资源图标保持彩色。等级位于市场行首，对应牌库剩余量显示在等级下方；卡号与完整说明可悬停查看。

宝石图标使用各自的轮廓：白钻为水滴形，蓝宝石为椭圆形，祖母绿为切角长方形，红宝石为钻石形，缟玛瑙保留八边形，黄金绘制为圆形金币。

暗抽牌背复用公共镭射卡组件，采用彩虹光与五种宝石错落铺开的轮廓刻纹，不叠加等高线。中央金币在暗处显示外轮廓，光点照过时显出币边、内圈与币面细纹，全部采用刻线，没有金色填充；周围宝石纹路避开金币，并保留间隔。所有暗抽牌背使用相同的排列，不从隐藏牌面生成图案。

发展牌、贵族卡与暗抽牌背使用公共 `HolographicCard`，游戏提供配色、刻纹、声望、宝石与费用内容；属性和复用方式见[公共镭射卡组件](../development/holographic-card.md)。镭射材质改编自 [vgpu 的 Holographic Card](https://vgpu.sh/examples/holographic-card)，将其波纹刻线、衍射与珠光反射移植到 WebGL，并按显示尺寸保持刻线间距。原示例采用 MIT 许可，版权与许可声明保留在 `apps/web/src/visuals/holographic.glsl.ts` 及网页的第三方许可中。减少动态效果时保持静态。

## 移动动画

市场购买的发展牌飞入对应玩家的卡牌背包，市场预留飞入预留区；暗抽从相应等级牌库飞出，途中统一显示牌背，落位后按当前视角展示。购买预留牌时，卡牌从预留区飞入背包。飞牌沿用实际卡面的声望、折扣、费用和镭射材质，不增加边缘发光；预留落牌时承接飞行中的光点，再平滑移回该卡的静止位置。选中卡牌后，卡面光点平滑移向中央，取消选中后平滑返回。拿取宝石时，每颗宝石从公共银行依次飞入该玩家的持有资源中，拿同色两枚与预留获得黄金也使用这一效果。

减少动态或静态画面时直接更新牌面和宝石。刷新、切换视角和重新开局不会重播历史动作，窗口调整或滚动改变目标位置时结束正在播放的移动。

Agent 玩家卡固定为 320px 并在玩家区域左对齐，预留牌位于对应玩家卡上方。

## 计分与下一局

计分板显示每位玩家的当局声望、已购发展牌数量与贵族数量。首局由名单第一位先手，替代实体规则中依年龄选先手；同桌下一局轮换先手、重新配置所有牌与 token，并按稳定玩家身份继承胜局和累计声望；累计成绩在结算中展示。
