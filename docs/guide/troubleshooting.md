## 连接与程序

| 现象 | 处理 |
| --- | --- |
| 连接不上 | 确认连接器已启动、浏览器允许本地网络访问，检查 origin 和端口配置 |
| 已被另一网页占用 | 在原网页断开连接，或关闭原游戏网页 |
| 提示协议或能力不符 | 下载当前网页要求的连接器，退出旧进程后启动新版 |
| 程序未找到或启动检测失败 | 在「可用程序」查看具体原因和选中的路径，按[连接器配置](connector.md#程序路径与自建网站)指定程序 |
| 能选模型但推理失败 | 在对应 Harness 中检查登录、模型权限与网络；WorkBuddy 独立 CLI 可能需要单独登录 |
| Agent 未完成决策 | 查看该玩家对话中的错误，处理原因后点击继续 |
| 刷新后暂停 | 当前桌仍在；点击继续会创建新会话并同步上下文 |
| 存档格式不匹配 | 新建游戏；开发期不迁移旧存档 |
| 保存失败 | 先导出要保留的公开记录，再使用提示中的「清理本地存储」；操作范围见[保存与导出](playing.md#保存与导出) |

## 超时与限流

每次决策的 180 秒时限包含 Harness 自己的限流重试。超时后连接器撤销本轮行动权限并取消上游任务；取消后 5 秒仍未结束，会关闭该玩家会话并暂停游戏。点击继续时重新建立所需会话。

上游暂时限流且程序明确表示会自行重试时，连接器只显示重试状态，让原生程序在本次决策时限内继续等待；也可以主动暂停。

上游最终返回 429 或明确的限流失败时，连接器才取消同一程序的活动决策并启动共享冷却。对话保留脱敏后的上游原因、错误代码和 HTTP 状态，需区分短时请求限流与账户额度耗尽。明确的 `Retry-After` 或恢复时间优先；程序未透传时保守等待 10 分钟，这是本地估计，不能保证账户额度届时恢复。

冷却期间重复点击继续不会发起请求，结束后需手动继续。Codex ACP 与 App Server 共用冷却，dsh、WorkBuddy 各自独立。重连、重建会话或重启连接器不会清除截止时间。3 秒发送间隔也不能保证消除所有 429。

开发时的安装、登录和模型目录诊断见[本地开发](../development/README.md#harness-诊断)。
